Routing Problem

路線優化

用 3 台車、9 個配送點視覺化 VRP。這頁是教學模擬：LLM 負責整理限制與產生草稿，真正最短路線仍要交給地圖 API 或最佳化演算法。

3台車 / 車手
9配送點
4時間窗風險
VRPVehicle Routing Problem
Van A 3 stops
Hub → A1 → A2 → A3 → Hub
風險：A2 需要上午送達，若 A1 延誤超過 20 分鐘要改順序。
Van B 3 stops
Hub → B1 → B2 → B3 → Hub
風險：B3 距離遠，適合給容量較大的車，避免午後回程塞車。
Van C 3 stops
Hub → C1 → C2 → C3 → Hub
風險：C2 是高價維修交付，需拍照簽收，不能只丟包。
LLM 做什麼讀訂單文字，整理站點、時間窗、重量、優先級，產生人能懂的路線草稿。
演算法做什麼計算距離、交換順序、平衡車輛負載，找真正比較短且符合限制的解。
人做什麼確認客戶承諾、特殊貨件、現場風險，避免 AI 把不能錯的事當成一般配送。

Routing Problem 是什麼

如果只有一台車，就是 TSP：一台車拜訪所有點，找最短順序。物流常見是 VRP：多台車、多個點、車容量與時間窗限制，目標是降低成本並準時完成。

Prompt 草稿

你是物流排程助理。
請把 9 個配送點分給 3 台車。
輸出：
1. 每台車的站點順序
2. 為什麼這樣分
3. 超時、超載、需簽收風險
4. 哪些地方需要人工確認
